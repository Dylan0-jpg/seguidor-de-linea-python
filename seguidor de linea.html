01 · Fundamentos

¿Qué es un Seguidor de Línea?

Un robot seguidor de línea es un sistema autónomo que detecta y sigue un camino marcado (usualmente una línea negra sobre fondo blanco) usando sensores ópticos. El control PID hace que lo siga con precisión y fluidez.

👁️

Sensores Reflectivos IR

Emiten luz infrarroja y miden cuánta rebota. El negro absorbe la luz (señal baja), el blanco la refleja (señal alta). Esta diferencia de voltaje es el "ojo" del robot.

⚡

Control On/Off vs PID

Un control simple dice "gira izquierda o derecha". El PID calcula cuánto girar en función del error actual, la velocidad de cambio y la acumulación histórica. El resultado es movimiento fluido sin zigzagueo.

🔄

Lazo Cerrado (Feedback)

El robot mide continuamente su posición relativa a la línea, calcula el error, ajusta los motores y vuelve a medir. Este ciclo se repite 100 veces por segundo.

📐

PWM — Control de Velocidad

La velocidad de un motor DC se controla con Modulación por Ancho de Pulso (PWM): una señal digital que varía su ciclo de trabajo del 0% (parado) al 100% (máxima velocidad).

🧮

Promedio Ponderado

Con 3+ sensores, la posición de la línea se calcula como una media ponderada: sensores extremos tienen mayor peso. Si la línea está a la derecha, el valor numérico sube.

🎛️

Sintonización Kp / Kd

Kp determina cuánto reacciona el robot al error actual. Kd amortigua las oscilaciones. Encontrar los valores correctos es el arte del control PID.

CASO PRÁCTICO — Temporización No Bloqueante

El cálculo derivativo del PID requiere un dt constante. time.sleep() bloquea el CPU y hace el dt impredecible. La solución: comparar timestamps con ticks_us() de MicroPython.

Python · MicroPython 
# ✅ CORRECTO: Temporización precisa con ticks_us()
from machine import ticks_us, ticks_diff

tiempo_anterior = ticks_us()
DT = 10000  # 10ms = 100Hz de control

while True:
    ahora = ticks_us()

    if ticks_diff(ahora, tiempo_anterior) >= DT:
        tiempo_anterior = ahora  # Guardar timestamp

        # ↓ Bucle crítico — se ejecuta exactamente cada 10ms
        leer_sensores()
        calcular_pid()
        actualizar_motores()

    # Otras tareas secundarias sin bloquear

# ❌ INCORRECTO — time.sleep() congela el CPU
# while True: time.sleep(0.01); calcular_pid()

CASO PRÁCTICO — PWM con LEDC

La ESP32 soporta PWM en MicroPython con la clase PWM de machine. Basta con crear un objeto PWM por pin — el hardware gestiona los canales automáticamente.

Python · MicroPython 
# Configuración PWM en MicroPython (ESP32)
from machine import Pin, PWM

PIN_ENA = 12  # ENA del L298N — Motor Izquierdo
PIN_ENB = 13  # ENB del L298N — Motor Derecho
FREC_PWM = 5000  # 5kHz — sin ruido audible

# Crear objetos PWM — MicroPython gestiona los canales automáticamente
motor_izq = PWM(Pin(PIN_ENA), freq=FREC_PWM, duty=0)
motor_der = PWM(Pin(PIN_ENB), freq=FREC_PWM, duty=0)

def set_motores(izq, der):
    # duty acepta 0..1023 en MicroPython (10 bits)
    izq = max(0, min(1023, izq * 4))  # escalar de 0-255 a 0-1023
    der = max(0, min(1023, der * 4))
    motor_izq.duty(izq)
    motor_der.duty(der)

  • Protección contra división por cero (robot fuera de pista)

CASO PRÁCTICO — Promedio Ponderado

Asignamos pesos -2000, 0, +2000 a los sensores izquierdo, central y derecho. Si la línea se va a la derecha, el valor resultante aumenta positivamente.

Python · MicroPython 
# Pines ADC válidos en ESP32 para los sensores
from machine import ADC, Pin

PINES = [34, 35, 32]   # Izq, Centro, Der
PESOS = [-2000, 0, 2000]  # Ponderación geométrica

# Inicializar ADCs con atenuación de 11dB (rango 0–3.3V)
sensores = [ADC(Pin(p)) for p in PINES]
for s in sensores:
    s.atten(ADC.ATTN_11DB)  # 0..4095 (12-bit)

def obtener_error():
    suma_pond  = 0
    suma_total = 0

    for sensor, peso in zip(sensores, PESOS):
        val = sensor.read()  # 0..4095 (12-bit)
        suma_pond  += val * peso
        suma_total += val

    # Protección: si no hay línea visible → sin corrección
    if suma_total == 0:
        return 0

    return suma_pond // suma_total
    # Retorna: -2000 (muy izq) ... 0 (centrado) ... +2000 (muy der)

Control en Lazo Cerrado PID

Algoritmo PD · Sintonización Kp/Kd · Mezcla diferencial
▾

Temas de la Unidad

  • Ecuación del controlador PID en tiempo discreto
  • Término Proporcional (P): reacción instantánea al error
  • Término Derivativo (D): amortiguación de oscilaciones
  • Término Integral (I): corrección de error estacionario
  • Por qué un controlador PD suele ser suficiente para seguir línea
  • Método de sintonización de Ziegler-Nichols simplificado
  • Mezcla diferencial: velocidadBase ± corrección
  • Restricción de rango con max(0, min(255, val))

CASO PRÁCTICO — Algoritmo PD Completo

Implementación completa del controlador PD. La corrección se suma a un motor y se resta al otro, generando la diferencia de velocidad que orienta el robot.

Python · MicroPython 
# Parámetros del controlador PD
Kp = 1.6    # Ganancia proporcional
Kd = 0.4    # Ganancia derivativa
BASE = 140  # Velocidad de crucero en rectas
error_ant = 0  # Memoria del ciclo anterior

def calcular_pd():
    global error_ant

    error = obtener_error()  # De la Unidad III

    # Términos del controlador
    P = Kp * error
    D = Kd * (error - error_ant)
    correccion = P + D
    error_ant = error  # Guardar para el próximo ciclo

    # Mezcla diferencial de potencia
    motor_izq = BASE + correccion  # Error (+) → aceleran izq
    motor_der = BASE - correccion  # Error (+) → frenan der

    # Limitar al rango válido del PWM (0–255)
    motor_izq = max(0, min(255, int(motor_izq)))
    motor_der = max(0, min(255, int(motor_der)))

    set_motores(motor_izq, motor_der)  # De la Unidad II

🐌

El robot reacciona lentamente. Se desvía de la línea sin corregir a tiempo, especialmente en curvas cerradas. Síntoma: pierde la pista en curvas.

Amortigua las oscilaciones de Kp. El robot se estabiliza rápidamente al centro. Un Kd excesivo produce movimiento rígido y lento.

06 · Referencia

Glosario Técnico

Términos clave del control PID y sistemas embebidos usados en este curso.

PID
Proporcional-Integral-Derivativo. Algoritmo de control en lazo cerrado que calcula una acción correctiva basada en el error actual, acumulado e histórico.
ADC (Analog-to-Digital)
Convertidor que transforma una tensión analógica continua (0–3.3V) en un número digital. La ESP32 usa ADC de 12 bits: 4096 valores posibles.
PWM (Pulse Width Modulation)
Señal digital que varía su tiempo en alto ("ciclo de trabajo") para simular un voltaje analógico. Permite controlar la velocidad de motores DC.
Puente H (H-Bridge)
Circuito con 4 transistores dispuestos en H que permite controlar la dirección y velocidad de un motor DC con señales lógicas de bajo voltaje.
Lazo Cerrado (Closed Loop)
Sistema de control donde la salida es continuamente medida y realimentada a la entrada para corregir desviaciones. Opuesto al control en lazo abierto.
Promedio Ponderado
Media matemática donde cada valor tiene un peso distinto. Permite calcular la posición relativa de la línea a partir de múltiples sensores.
LEDC (ESP32)
Periférico hardware de la ESP32 para generar señales PWM precisas. Soporta 16 canales independientes con frecuencias y resoluciones configurables.
Kp / Kd (Ganancias)
Constantes de ajuste del controlador PD. Kp determina la fuerza de reacción al error. Kd amortigua las oscilaciones. Deben sintonizarse experimentalmente.
dt (Delta Time)
Intervalo de tiempo entre muestras del controlador. Debe ser constante para que el término derivativo sea matemáticamente correcto.
